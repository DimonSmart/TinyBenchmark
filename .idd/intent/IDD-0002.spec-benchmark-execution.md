# IDD-0002.spec-benchmark-execution

## Intent

TinyBenchmark помогает разработчикам сравнивать время выполнения альтернативных
функций при разных входных значениях, сохраняя отдельные измерения для анализа.

## Related Specifications

- IDD-0003 определяет представление и экспорт результатов измерений.

## Behavior

### Выбор benchmark-сценариев

Пользователь отмечает методы для измерения и может явно выбрать классы для запуска.
Без явного выбора библиотека обнаруживает отмеченные методы в загруженных
компонентах. При таком обнаружении наличие классов с отметкой приоритетного выбора
ограничивает запуск этими классами; явный выбор классов остаётся определяющим.

Поддерживаются синхронные методы без аргументов либо с одним аргументом. Значения
аргумента задаются одной отмеченной параметрической характеристикой класса:
явным набором значений либо целочисленным диапазоном с включённой нижней,
исключённой верхней границей и положительным шагом. Каждая пара метода и значения
образует отдельный сценарий. Несколько параметрических характеристик в одном
классе недопустимы.

### Повторения и длительность

Пользователь задаёт минимум и максимум измерительных повторений для каждого
сценария. Минимум положителен, максимум не меньше минимума. После достижения
минимума измерения заканчиваются при достижении максимума или выделенного
временного бюджета. Без бюджета длительности измерения заканчиваются после
достижения заданного минимума.

При использовании бюджета длительности предварительный прогрев выполняет
заданное пользователем число запусков и позволяет оценить относительную стоимость
сценариев для распределения бюджета. Бюджет является ориентиром длительности
измерений: минимум повторений, прогрев и служебные операции могут увеличить
фактическое время запуска. Уже начатый вызов не прерывается по истечении бюджета.

### Измерения

Результат сохраняет принадлежность к классу, методу и входному значению, а также
отдельные измерения времени выполнения и времени измерительной операции.
Измерение может охватывать пакет вызовов; его интерпретация должна позволять
отличить время пакета от времени одного вызова.

По выбору пользователя измеряется оценка объёма выделенной памяти за интервал
измерения. Это не точное количество памяти, принадлежащей конкретному методу,
и не показатель удерживаемой памяти: возможен вклад других операций в общем
контексте выполнения. Без включения этой опции память не измеряется.

Пользователь может подключить журнал сообщений о ходе запуска. Полученные данные
доступны для последовательного применения разных способов экспорта.

## Product-Significant Architecture And Constraints

Benchmark-код выполняется локально в контексте вызывающей программы. Версия
платформы, язык и используемые пакеты не являются обязательными ограничениями
продукта. Совместимость с прежними API и поведением по умолчанию не требуется.

## Non-Goals

- Гарантия строгого предельного времени завершения запуска.
- Изоляция измерений от всех влияний окружения.
- Точное определение удерживаемой памяти конкретного метода.
- Измерение асинхронных методов и методов с несколькими аргументами.

## Acceptance Criteria

- Явный выбор классов и автоматическое обнаружение выбирают соответствующие
  отмеченные методы; приоритетная отметка ограничивает автоматический выбор.
- Методы без аргументов запускаются без параметра; параметризованные методы
  получают каждое заданное значение, включая корректные границы диапазона.
- Каждый сценарий получает минимум измерительных повторений и не превышает
  заданный максимум измерительных повторений.
- Прогрев при использовании бюджета соблюдает заданное число запусков.
- Достижение временного бюджета не отменяет минимум и не прерывает вызов.
- Результаты различают сценарии, отдельные измерения и интерпретацию пакета.
- Оценка памяти включается явно и не представляется как точный расход метода.

## Verification

Автоматизированные проверки подтверждают выбор сценариев, параметризацию и
границы диапазонов, допустимость ограничений повторений, число прогревочных
запусков и завершение измерений при разных сочетаниях бюджета и количества.
Проверки результатов подтверждают связь измерений со сценарием и различение
времени вызова и пакета. Проверка опции памяти подтверждает её добровольное
включение и ограниченную интерпретацию оценки.
